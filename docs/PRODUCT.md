# PRODUCT — 产品定义

> 设计原则见 [VISION.md](VISION.md) · 架构见 [SYSTEM-DESIGN.md](SYSTEM-DESIGN.md)（现行总体设计；`ARCHITECTURE.md` 已于 DOC-03 降级为**拆仓前历史 Reference**，不再作现状依据）· 待办见 [TASKS.md](https://github.com/ruoxizhnya/tellurion/blob/main/docs/TASKS.md)

## 一句话

自托管的 A 股量化研究平台。**AI 是操作回测底座的实验员，人是实验室主任**——AI 负责产出与试错，人负责判断与拍板。

---

## 为谁解决什么

**用户**：我自己（若曦）。第一个用户即开发者，自托管、单人、非 SaaS。

**我的处境**：谨慎型投资者，有一定判断力，但——

- 策略面太窄，能下手的打法就那么一两种
- 人工验证一个想法太慢，跟不上建立信心所需的样本量
- 不理解因果的东西不敢用，纯统计显著的因子看了也不会碰
- 一个人做不完研究，需要一个能干活的"初级研究员"

**核心死锁**：越谨慎 → 实盘样本越少 → 越难建立信心 → 越不敢交易。
本产品用来打破它：**在不实盘的前提下，快速、大量、可解释地验证投资逻辑。**

---

## 三个角色 + 一座底座

| 角色 | 是谁 | 干什么 | 关键约束 |
|---|---|---|---|
| **实验室主任** | 我（人） | 给方向、批阅、拍板 | 不下场操作仪器 |
| **AI 实验员** | Hermes agent | 操作底座：挖因子、调系数、跑回测、看结果 | 交付**提案**，不是结论 |
| **验证器**（validation subagent） | 验证方 | **主动证伪**，不是复现 | **被调用**，不自主循环；看保留数据 + 实验日志，看不到实验员推理 |
| **底座** | 系统 | 行情 / 财务 / 因子 / 回测 / 证据 + 验证器链 | 确定性，无人值守 |

**为什么必须是验证器而不是"再跑一遍"**：用同一把尺子量第二次，置信度不会增加（1.0 × 1.0 还是 1.0）。只有换一种错误来找，两边的结论才会真正相乘。

## 系统构成：五种角色，一座底座

> 只写**功能角色**。仓级清单（谁管什么 / 拥有哪块 schema / 对外面 / 状态）唯一在 [REPO-MAP.md](REPO-MAP.md)，本节刻意不复制——同一事实写两份必然漂移。

| 角色 | 在产品里干什么 | 由哪些仓承担 |
|---|---|---|
| **仪器** | 回测 / 撮合 / 组合结算 / 策略运行时 / 仪器域存储——给定输入必有确定输出，可无人值守 | `tellurion`（core）。**一名多角色**：它既是仪器本体，又是仪器域数据的唯一写者 |
| **实验员** | 挖因子、调系数、跑回测、看结果、决定下一步（唯一会自主循环的那个） | `tellurion-agent` |
| **观察窗** | 让人能审阅、能干预、能拍板（5 分钟知道该关注什么） | `tellurion-ui` |
| **扩展舱** | 数据面 / 策略资产 / 风控规则 / 编排 / 交易通道——按需触发、可独立部署的能力单元 | `tellurion-data` · `-strategy` · `-risk` · `-orchestration` · `-broker` |
| **参考实现** | 独立只读的指标 / 分析参考实现：单仓自证可用，验证方法论，不接生产热路径；**core 调用方为 0 是设计不是缺陷** | `tellurion-analytics`（本仓 ADR-0005：独立只读参考实现，core 指标保留并冻结、不迁移） |
| **契约底座** | 跨边界只交换**形状**与**纯技术能力**，不交换实现 | `tellurion-contracts`（port / DTO / 值对象 / 哨兵错误）+ `tellurion-kit`（日志 / 十进制 / 统计 / DB 连接…） |

**扩展舱不是"已经如此"的名单。** 截至 2026-11-11，core 真正消费的远程能力是：`tellurion-data` 的回测取数；`tellurion-strategy` 的非空 `strategy_ref` resolve（出厂启用）；`tellurion-risk` 的限额快照 `resolve`（出厂 true，事件回传仍出厂 false）；`tellurion-broker` 的唯一下单通道（core 进程内 `MockTrader` 已退役）；`tellurion-orchestration` 的任务队列（worker 进程仍在 core）。`tellurion-analytics` **不在这张名单里**：它的定位是参考实现（本仓 ADR-0005），core 调用方为 0 是设计而非待接线项。逐条接线现实以 [SYSTEM-DESIGN.md](SYSTEM-DESIGN.md) §4/§5 为基准、随施工漂移，所以刻意**不写进上面这张角色表**。

**为什么产品叙事不数进程**：承重句是「AI 操作底座、人拍板」。底座拆成几个可独立部署的单元，不改变这句话；拆与不拆的判据是**热路径不出进程**（[SYSTEM-DESIGN.md](SYSTEM-DESIGN.md) §2 的 P1），不是"服务越多越像平台"。

## 三层结构

```
L3  AI 编排层    AI 实验员（唯一编排者，会循环） · 因果审查（被调用，不循环）  ← 唯一需要人在环
L2  能力层       [MCP 工具桥] → 因子计算 | 回测 | 产业链查询（后端 ✅ / 仅 API，无 UI 入口） | 证据查询 | 验证器链×5   ← 禁止 AI 直接摸数据
L1  数据层       行情 | 财务 | 产业链图谱 | 研究洞察 | 实验日志
```

- **AI 只能调能力层，能力层才能碰数据。编排者只有一个**（Hermes）——会自主循环、决定下一步的只有它。
- **实验日志落在 L1**：由 AI 产生、经能力层写入，被验证器与审阅台共同读取——它是过拟合检测、路径回放、复盘的共同数据源，不是附属功能。
EquityDeep 提供数据与洞察（产业链图谱 + 研究洞察库），**不做独立编排**。

**能力状态（2026-11-13 实测）**：
- **产业链查询：后端可用，仅 API（无 UI 入口）** —— core `docs/openapi.yaml` 已收录 `Industry (P2-2)`（行业树 / 供应链边 / 行业活力 / ETF 成分）与 `Macro (P2-1)`（宏观序列）；UI `web/src` 零 `industry` 命中。2026-11-13 已裁决**当期仅 API、不做界面**（[ODR-074](archive/odr/odr-074-rulings-on-nine-suspended-tasks.md) D6）；建页触发条件 = **S2 出口**（至少 1 个行业假设因子完成验证并带 `hypothesis_source`）。性质 = **能力已具备、未暴露**，不是未实现。
- **因果来源（`hypothesis_source`）：未实现，维持挂起** —— S2 中该项尚未开始（产业链底座已达成，见 [ROADMAP.md](ROADMAP.md) §S2）；12 仓代码零命中。2026-11-13 裁决**维持挂起至 S1 出口**（ODR-074 D9），字段形状由真实探索数据决定。性质 = **确实缺功能**，不随本页文案改善。

## 用户流程：异步审阅三节奏

我不盯着看，也不该盯着看。三种节奏：

| 节奏 | 耗时 | 做什么 |
|---|---|---|
| **给方向** | 30 秒 | "这周看光模块" + 约束（行业 / 窗口 / 别碰什么） |
| **看摘要** | 5 分钟 | "试了 380 次，值得你看的 3 个"——每个配**路径缩略图** + **质疑清单** + **概率估计** |
| **深挖回放** | 按需 | 完整探索路径：从哪开始、怎么走到这、放弃过什么方向 |

**摘要排序不按 IC 排，按「高原面积 × 因果强度」排。**

四个必须能做的干预动作：**叫停 / 指方向 / 追问（为什么放弃这个方向）/ 标记（围绕它多试）**。
其中"追问"最有价值——**AI 放弃的方向比它选中的更有信息量**。

## 漏斗：宽进严出

```
① 候选生成 · 要宽    AI 挖掘 + 产业链认知 + 多源信息 → 数百条（错了没成本）
② 统计初筛 · 自动    样本外 + 参数敏感度 + 多重检验校正 → 数十条
③ 因果解释 · 关键    讲得出为什么吗 → 数条（EquityDeep 主战场）
④ 我的信心门槛       1-2 条（错了有成本，所以最严）
        ↓
持续监控：市场状态 + 策略漂移 → 失效即回流到 ①
```

**过拟合防护是操作回路的免费副产品**：AI 每调一次底座就留一条日志，"试了多少次"这个数字天然可得——而过拟合的核心判据正是它。所以先跑通回路、把日志记全，防护后面再算。

**AI 挖的是这七维空间里的一个点**：① 因子表达式 ② 系数/参数 ③ 股票池 ④ 持有期 ⑤ 合成权重 ⑥ 过滤条件 ⑦ 买卖规则。每一次"挖"= 调底座跑一次。

## 验证器：5 个确定性校验器 + 1 个因果审查

**编排者只有挖掘 agent（Hermes）。验证器是被调用的，不自主循环**——输入提案 → 运行一次 → 输出质疑清单 → 结束。

| 维度 | 性质 | 归属 | 内容 |
|---|---|---|---|
| 统计 | 确定性 | **L2** | 多重检验校正（试了 N 次，门槛就按 N 收紧） |
| 经济 | 确定性 | **L2** | 扣费后净收益 |
| 稳健 | 确定性 | **L2** | 参数敏感度、分年度、分市值/行业 |
| 偏差 | 确定性 | **L2** | 前视、幸存者、复权口径 |
| 冗余 | 确定性 | **L2** | 与已有策略相关性（防"伪分散"） |
| **因果** | 需语义理解 | **L3** | 讲得出为什么吗 |

> **六个维度里五个是纯计算，不需要 LLM。** 只有"因果"一项真正需要语言模型——这让验证器的成本和不确定性都低一个量级。

| | 挖掘 agent | 验证器 |
|---|---|---|
| 能看到 | 训练期数据 + 全部工具 | **保留期数据** + 提案 + **完整实验日志** |
| 看不到 | 保留期数据（防偷看） | 挖掘 agent 的推理过程（防锚定） |
| 输出 | 候选 + 因果来源 | **概率估计 + 质疑清单**（不是通过/不通过） |

验证器必须看到实验日志：**试 5 次撞出来的和试 500 次撞出来的，同样结果，可信度差一个量级。**

---

## 目标是可校准，不是准确

> 系统说"60% 把握"，就该真的 60% 命中。

再严格的验证也只能证明历史稳定，不能保证未来有效。**但校准良好的信心可以拿来配仓位**——不准却表现得很有把握，才会让人重仓受伤。

**因此系统的考核指标是校准误差，不是推荐准确率。**

## 边界

| 不做 | 理由 |
|---|---|
| 投资建议 / 目标价 / 评级 | 系统提供验证过的假设与置信度，**决策权在人** |
| 实时行情 / 盘中监控 | 按财报期驱动，日频已是高频边界 |
| 多 agent 投票 / arbitrator 仲裁 | 错误相关、放大偏差、不可解释 |
| 让 EquityDeep 成为第二个 agent | 它提供数据与洞察，不做独立智能流程 |
| 实盘证券状态校验（停牌 / 退市 / 强平） | 只在真实柜台下成立；已裁决随实盘通道退役（ODR-074 D1） |
| 期权 / 两融 / 集合竞价撮合 | 无数据源、无 broker 面、不在任何阶段；代码包已裁决退役（ODR-074 D3） |
| 产业链 / 宏观 UI 页面 | 观察窗页面须绑定用户动作；S2 出口前只有 API（ODR-074 D6） |
| 浅色主题 / 主题切换 | 深色是唯一经设计验收的基线；控件已裁决移除（ODR-074 D7） |
| SaaS / 多租户 | 服务单个个体 |

### 数据从哪来 / 多久可评 / 能否回填（2026-11-13 核证）

> 结论先说：**四个指标都"能测"，但都不"可回填"**。回填能力受两条硬约束：① 采纳与实验日志是**人工/AI 运行时产生**，无外部源可重放；② 宿主 PG **没有备份**（ODR-072 于 2026-11-11 登记为 High：不可重建实验资产单副本）。因此本节只写真能兑现的口径，不承诺"事后补齐"。

| 指标 | 数据来源（责任仓） | 积累窗口 | 能否回填 | 依据 / 缺口 |
|---|---|---|---|---|
| 月度可用策略数 | `ai.adoption_ledger`（agent），人工经 `POST /api/pipeline/adoption` 写入 | ≥1 个自然月 | **否**：采纳是人的判断，无法事后重建；漏记只能补录并标注补录日期 | 端点与表已落地；无自动采集 |
| 校准误差 | `ai.adoption_ledger` × 采纳项实际表现（core `run.backtest_results`） | ≥6 个月连续记录（自首条采纳记录起算） | **部分**：满 6 个月的结论可算；core 结果面保留期为明细 90 天 / 汇总与 provenance 365 天，超期原始结果不可回填 | `CORE-RESULT-RETENTION`（core `cmd/analysis/main.go`，默认启用） |
| 验证吞吐量 | `ai.experiments`（agent） | ≥1 个自然月 | **否**：日志随实验运行产生，没有可重放的外部事实源 | 表与计数端点已落地 |
| 证据覆盖率 | `ingest.raw`（data）+ JSON Pointer（**未实现**） | 即时（按记录计） | **否**：JSON Pointer 未落，覆盖率当前无法机械计算，更谈不上回填 | 已知部分实现，见上表 |

- **数据库备份**：无（ODR-072 High，2026-11-11 实测「宿主 PG 无备份」）⇒ 上述数据均为单副本，库损即不可恢复。修备份属运维/跨仓任务，不在本页承诺范围内；本页只如实标注。
- **CI artifact 不是测量源**：UI e2e 报告保留 7 天（`tellurion-ui:.github/workflows/ci.yml`），core 覆盖率产物同理，均不承载产品指标。
- **报表脚本**：目前没有独立的指标报表脚本；`/api/pipeline/*` 三个只读端点就是全部读数面。
